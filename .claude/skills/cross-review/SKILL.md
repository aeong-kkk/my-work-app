# Cross Review — GPT × Claude 교차검증

## 무엇을
사용자가 지정한 문서/파일 하나를 두 가지 독립적인 시각(OpenAI GPT API, Claude 자신)으로 각각 검증한 뒤, 두 결과를 대조해 "공통 지적 / 한쪽만 지적 / 서로 엇갈리는 지적"으로 정리해 보여준다. 문서 자체를 다시 쓰지 않는다 — 지적까지만 한다.

## 점검 기준 (양쪽 검증 공통)
- 사실: 숫자·이름·날짜·인용 중 근거 없이 지어낸 것으로 의심되는 부분
- 논리: 주장과 근거가 맞지 않는 부분
- 누락: 꼭 있어야 하는데 빠진 내용
- 톤·형식: 받는 사람 기준으로 어색하거나 부적절한 부분

## 입력
- 검증할 파일 1개 (사용자가 `@파일` 또는 경로로 지정)
- (선택) 근거/참고 파일 — 검증 대상의 사실관계를 대조할 관련 스펙·코드·문서. 프로젝트 안에 명확히 관련된 파일(같은 내용을 다루는 다른 스펙 문서, 그 스펙을 구현한 코드 등)이 있으면 사용자에게 묻지 않고 알아서 포함하고, 애매하면 사용자에게 확인한다.
- `OPENAI_API_KEY`가 `.env`에 설정돼 있어야 한다 (기능 2~6과 동일한 키 사용).

## 순서
1. **GPT 검증**: `python feature7_cross_review.py <검증할 파일> [근거 파일 ...]`을 실행한다. 스크립트가 대상 파일과 같은 폴더에 `<파일명>-gpt-review.md`를 자동 생성한다. **이 시점에 그 파일을 열어서 읽지 않는다.**
2. **Claude 독립 검증**: gpt-review 파일 내용을 보지 않은 상태에서, 검증 대상 파일(과 1번에 쓴 것과 동일한 근거 파일들)을 직접 읽고 같은 네 가지 기준으로 문제점을 짚는다. 각 지적은 "어느 문장인지 + 왜 문제인지"를 짧게 적는다.
3. **비교**: 2번을 마친 뒤에야 `<파일명>-gpt-review.md`를 읽는다. 두 검증 결과를 다음 세 갈래로 나눠 표로 정리한다.
   - 공통으로 지적한 것 → 확실히 고칠 후보
   - 한쪽만 지적한 것 → 확인해볼 것
   - 서로 엇갈리는 것 → 각 근거를 함께 적기
4. 표를 사용자에게 보여준다. 실제 문서 수정은 사용자가 반영할 지적을 고른 뒤 별도로 진행한다 (이 스킬은 지적까지만 하는 범위).

## 출력
- `<검증할 파일명>-gpt-review.md` (GPT 검증 결과, 대상 파일과 같은 폴더에 저장)
- 채팅에 표시되는 공통/한쪽만/엇갈림 비교 표

## 주의사항
- 순서를 반드시 지킨다: GPT 검증 → (gpt-review 안 보고) Claude 독립 검증 → 그다음 gpt-review를 읽고 비교. 순서가 바뀌면 Claude 검증이 GPT 결과에 오염되어 "독립적" 검증이 아니게 된다.
- 이 스킬은 지적만 한다. 사용자가 반영할 지적을 고르기 전까지 대상 파일을 수정하지 않는다.
