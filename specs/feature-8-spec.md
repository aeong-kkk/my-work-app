# 기능 8 — 발주 정보로 견적서(고객제출용) + 발주서(FPE PO, 내부보관용) 자동 작성

> 발주 후 사람이 매번 손으로 `견적서작성 양식.xlsx`를 열어 층/TYPE/개취수를 계산기에 넣고,
> Customer 시트와 FPE PO 시트에 모델명·수량을 옮겨 적던 작업을 자동화한다.
> 기능 1(`feature1_extract_order.py`)이 이미 추출한 발주 정보를 재사용하고,
> 사람 입력이 필요한 값(TYPE, 제품 개취수)만 별도로 받는다.

## 무엇을 하는 기능인가
발주시트에서 뽑은 모델명·내부명·층구성·수량 정보와, 사람이 입력한 TYPE·제품 개취수를
`견적서작성 양식.xlsx`의 계산기(PRICE_DB 시트)와 두 출력 시트(Customer/FPE PO)에 채워
넣어, 고객제출용 견적서와 내부보관용 발주서(FPE PO)를 한 번에 만든다.
단가 계산 수식 자체는 건드리지 않고, 기존 계산기가 하던 계산을 그대로 활용한다
(엑셀에서 열면 자동 재계산됨).

## 입력
- 발주시트 1개 (기능 1과 동일한 `order sheet.xlsx` 형식) — `feature1_extract_order.py`의
  `extract_order_records()`를 그대로 호출해서 모델명·내부명·층구성·수량을 가져옴
  (한 발주에 수량 행이 여러 개면 — 분할입고 등 — 견적서는 행별이 아니라 **전체 수량 합계
  기준으로 1건만** 작성함)
- TYPE (예: "Interposer") — 사람이 직접 입력/선택
- 제품 개취수 (예: 500) — 사람이 직접 입력
- 툴비(Tool Charge) 포함 여부 — 사람이 선택 (포함/미포함), 기본은 포함
- 견적서 양식 파일 (`inputs/견적서작성 양식.xlsx` 같은 구조, 시트 3개: PRICE_DB / Customer / FPE PO)

## 항목 매핑
| 항목 | 출처 | 비고 |
|---|---|---|
| 층 (PRICE_DB!I3) | 발주시트 층구성(G19) 파싱 | 예: "10L/FVSS3" → "L" 앞 숫자만 추출 → 10 |
| TYPE (PRICE_DB!I4) | 사람 입력 | 자동화 불가, 매번 입력/선택 |
| 제품 개취수 (PRICE_DB!I5) | 사람 입력 | 자동화 불가, 매번 입력 |
| 모델명 (Customer!B16) | 발주시트 모델명(F5) | |
| 층구성 (Customer!B17) | 발주시트 층구성(G19) 원문 그대로 | 파싱 전 원문 표시용 |
| 수량 (Customer!G16) | 발주시트 수량(Shipping Information I열) 전체 합계 | 행이 여러 개(분할입고 등)여도 합쳐서 1건으로 작성 |
| 툴비 수량 (Customer!G20) | 사람이 선택한 포함 여부 | 포함=1(기존 템플릿 기본값 유지), 미포함=0 (Q20=0이 되어 합계에 영향 없음) |
| 단가·Sample Code 등 | PRICE_DB 계산기 수식이 자동 계산 | 파일에 이미 있는 수식 그대로 사용, 값만 안 건드림 |
| FPE PO 모델명/수량 (FPE PO!B21/F21) | Customer!B16/G16 수식으로 자동 연결 | 이미 파일에 있는 수식, 그대로 둠 |
| FPE PO 단가 (FPE PO!I21) | **PRICE_DB!I9 ("FPE 단가" = 고객단가 ÷ 1.035, 3.5% 마진)** | 현재 파일엔 이 셀이 수식 연결이 안 되어 있고 수동값 — 이번에 `=PRICE_DB!I9` 수식으로 연결해서 채움 (템플릿 보완) |

## 동작
1. 발주시트 파일을 받아 `extract_order_records()`로 모델명/내부명/층구성/수량(행별) 추출
2. 행별 수량을 모두 합산 → 전체 수량 (모델명/내부명/층구성은 모든 행이 같으므로 첫 행 값 사용)
3. 층구성 문자열에서 "L" 앞의 숫자만 추출 (정규식) → 층 값. 형식이 예상과 다르면(숫자+"L" 패턴이 없으면) 에러로 알림
3-1. PRICE_DB 원본표에서 층수+TYPE 조합이 실제로 존재하는지 확인 — 층수마다 쓸 수 있는 TYPE이 정해져 있어서(예: 층 2는 "Interposer"만, 층 10은 "C"/"D"/"3D" 등만), 없는 조합이면 에러로 알리고 그 층수에서 쓸 수 있는 TYPE 목록을 보여줌 (안 그러면 엑셀에서 단가가 조용히 빈 값/오류로 나옴)
4. TYPE, 제품 개취수, 툴비 포함 여부를 사람에게 입력받기 (대화형 또는 인자)
5. 견적서 양식 파일을 열기 (수식은 그대로 유지 — `data_only=False`로 읽고 써야 수식이 안 사라짐)
6. PRICE_DB 시트 I3(층)/I4(TYPE)/I5(제품 개취수)에 값 쓰기
7. Customer 시트 B16(모델명)/B17(층구성 원문)/G16(전체 수량) 값 쓰기
8. 툴비 포함이면 Customer!G20 = 1(기존 값 유지), 미포함이면 0으로 덮어씀
9. FPE PO 시트 I21에 `=PRICE_DB!I9` 수식이 없으면 추가 (있으면 그대로 둠)
10. 결과 파일을 `outputs/견적서_<모델명>_<발주일>.xlsx` 이름으로 저장 (원본 양식 파일은 다시 쓰지 않음)
11. 저장 안내 메시지 출력 — "엑셀에서 열면 단가 등이 자동으로 계산되어 보입니다" 안내 (수식 재계산은 엑셀이 파일 열 때 수행하므로, 이 스크립트가 직접 계산 값을 보여주지는 않음)

## 출력
- 완성된 견적서 파일 1개 (.xlsx, `outputs/견적서_<모델명>_<발주일>.xlsx`) — Customer 시트(고객제출용)와 FPE PO 시트(내부보관용)가 한 파일 안에 함께 들어있음
- 사람이 엑셀로 열어서 최종 확인 후 고객에게 전달 (이 기능은 초안 작성까지만 하고 최종 확인은 사람 몫)

## 지금은 뺄 것
- Customer 시트의 고객사명(Attention)·주소 등 레터헤드성 항목 자동화 — 이번 범위 밖, 기존처럼 사람이 직접 채움
- 화면(Streamlit) 연동 — 이번엔 스크립트/함수 단위로만 동작 확인
- 여러 건 한 번에 처리 — 이번엔 1건 처리에 집중
- FPE PO 시트의 툴비(Tool Charge) 라인 — 원본 템플릿에도 단가·합계 수식이 없어 이번에도 자동화 대상에서 뺌 (사람이 필요시 직접 채움)

## 참고
- `inputs/견적서작성 양식.xlsx`의 Customer 시트에 실제 고객사명(삼성전자)이 들어있으므로,
  이 파일을 계속 참고 자료로 쓰거나 커밋하기 전에 가짜 고객사명으로 바꿔야 함
  (`CLAUDE.md` 절대 규칙 — 실명·실제 사내 자료 금지)
