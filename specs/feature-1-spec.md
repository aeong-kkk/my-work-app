# 기능 1 — 발주 엑셀에서 정보 추출 + 리드타임 계산

> 기획서(sample-order-listing-plan/pitch/flow.md) 기준, "개발샘플현황표 자동화" 전체 흐름(27단계) 중
> 가장 먼저 만들면 좋은 핵심 기능으로 이 부분을 선정했습니다. 나머지 단계(다중 파일 처리, 중복 검사,
> 리스트 파일 누적 저장, UI)는 이 기능이 정상 동작한 뒤에 그 위에 얹는 구조입니다.

## 무엇을 하는 기능인가
발주 엑셀 파일 1개(Info 시트)를 읽어 모델명·내부명·수량·요청일·Total-T(板厚)·층구성(层构成)을 추출하고, 리드타임(일수, 요청일-발주일)까지 계산해 결과 행(들)으로 돌려주는 기능이다.

## 입력
- 발주 엑셀 파일 1개 (Info 시트 1개뿐 — 예전에는 Packing 시트가 따로 있었지만, 지금은 Info 시트 안 "Shipping Information" 구역(I열~)으로 통합됨)
- 발주일은 파일 안(Info 시트 G1)에 직접 기입되어 있음
- 신규발주/재발주 구분은 파일 안(Info 시트 F3, "NEW／Repeat" 항목)에 직접 기입되어 있음
- 수량·요청일은 Info 시트의 "Shipping Information" 구역에서 행마다 하나씩 기입됨(I열=수량, M열=요청일, 3행부터 시작) — 예전의 "단일 발주(F7/F15)"와 "분할 발주(Packing 시트)" 구분이 없어지고, 이 구역 하나로 통일됨

## 동작
1. 파일에 "Info" 시트가 있는지 확인 — 없거나 구조가 다르면 에러 반환하고 종료
2. Info 시트 G1 값 읽기 → 발주일
3. Info 시트 F3 값 읽기 → 신규발주/재발주 구분 ("New"/"Repeat")
4. Info 시트 F5 값 읽기 → 모델명 (Customer Model Name)
5. Info 시트 F6 값 읽기 → 내부명 (Internal Model Name)
6. Info 시트 G18 값 읽기 → Total-T (板厚)
7. Info 시트 G19 값 읽기 → 층구성 (层构成)
8. "Shipping Information" 구역에서 I열(3행부터) 값이 입력된 행을 전부 확인 — 값이 하나도 없으면 에러
9. 확인된 행 개수만큼, 각 행의 I열 → 수량, M열 → 요청일로 결과 생성(발주일/구분/모델명/내부명/Total-T/층구성은 모든 행에 공통 적용)
10. 요청일에 연도 보정 적용 (예: "6/30" → "2026-06-30")
11. 행이 여러 개면서 요청일이 서로 다르면, 그중 가장 늦은 요청일인 행은 구분 값을 "분할입고"로 덮어씀 (원래 신규발주/재발주였어도 적용됨). 행이 1개거나 요청일이 전부 같으면 적용 안 함
12. 수량 값에서 숫자만 분리 (예: "16\n(IST Coupon)" → 16)
13. 값 앞뒤 공백·줄바꿈 제거
14. 발주일·요청일로 리드타임(일수) 계산 = 요청일 - 발주일 (행별로 계산)
15. 필수 항목(발주일/요청일/구분/모델명/내부명/Total-T/수량/층구성) 비어있는지 확인 → 비어있으면 "누락" 플래그 추가
16. 정리된 값들을 결과 행(들)으로 묶어서 반환

## 출력
- 결과 행 배열 (데이터 형태 — 파일/화면 저장 아님)
- 컬럼: 발주일 / 구분(신규발주·재발주·분할입고) / 요청일 / 모델명 / 내부명 / Total-T / 수량 / 층구성 / 리드타임(일수) / 비고("누락" 플래그, 없으면 빈 값)
  - 분할입고 — 한 파일 안에 요청일이 서로 다른 행이 여러 개 있을 때, 그중 가장 늦은 요청일인 행에만 붙는 구분값 (원래 신규발주/재발주였는지와 무관하게 덮어씀)
- "Shipping Information" 구역에 행이 여러 개면 한 파일에서 여러 결과 행이 나옴 (발주일·구분·모델명·내부명·Total-T·층구성은 동일, 수량·요청일·리드타임·비고만 행마다 다름)
